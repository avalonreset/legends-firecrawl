# Release scope: 0.2.0

Planned stable release based on router-native 0.1.0. This document defines scope; it does not establish publication or installation status.

## Official Firecrawl only

All data execution uses official Firecrawl services. All native/direct-source substitutions are retired, including the two Treasury operations briefly considered for the 0.2.0rc1 allowlist. There is no direct bypass mode or automatic native fallback in the supported product.

Alexandria queries default to a request preview and require explicit `--confirm` before submission. Crawl jobs retain bounded scope and explicit confirmation. Other existing web operations may charge on execution; the Alexandria preview rule is not a blanket rule for every command.

## Product value

- A consistent agent-facing CLI in the `cto-legends` workflow.
- Offline catalog browsing and provider inspection.
- Bounded job controls and reviewable request submission.
- Saved response provenance and research captures.

These are workflow features. They are not a proprietary data source, a guarantee of better data than Firecrawl, or a credit-saving system. Firecrawl already offers free discovery, and its API and CLI also do not require MCP.

The saved catalog contains 114 provider labels and 797 capabilities. Those are snapshot counts, not evidence that every provider and operation has been executed successfully. Current contracts and prices may differ.

## Historical experiment

The [October 1 audit](NATIVE-LIVE-AUDIT-20261001.md) is retained as historical evidence. It found narrow field matches on Treasury, partial SEC and USAspending comparisons, CourtListener record-identity matches, incorrect YC and ESPN substitutions, and a Wayback rate-limit failure. That research does not authorize any direct execution in 0.2.0.

Earlier 72/114 classification, 63.2% savings, zero-risk access and proxy-shielding claims are withdrawn. Neither broad savings nor sustained-scale direct reliability was established. Selling managed access to public records is not evidence of a scam; maintained integration, normalization and enrichment can provide value.

Historical captures remain unchanged. Their old routing and safety labels describe prior runs and are not current product policy. Existing research notes retain their paths for provenance, with retired status displayed prominently. Future direct integration work requires a new explicit product decision; it is not a promised feature of this release.
